## 1. Назначение

«Сквозняк» — одноместный небесный парусник. Маленькая герметичная кабина подвешена под огромным кольцом из шести складных парусов. Паруса ловят воздушные потоки, удерживают кабину и позволяют двигаться. Чем сильнее ветер в допустимом диапазоне, тем выше скорость полета, но не выше установленного ограничения. В штормовом режиме управление расходует больше энергии. В штиль аппарат летать не может, чрезмерный ветер также вынуждает его садиться.

![Небесный парусник «Сквозняк»](docs/skvoznyak.png)

## 2. Стихия и конструкционный элемент

**Стихия:** воздух.

**Обязательный конструкционный элемент:** кольцо из шести складных парусов-захватов, использующих воздушные потоки для подъемной силы и движения.

В модели исправный парус обеспечивает 50 кг несущей способности. `lift_capacity_kg = working_sails * 50`. Для удержания аппарата нужны раскрытые паруса, минимум три исправных паруса, масса не больше несущей способности и ветер от 10 до 60 км/ч включительно.

Энергия аккумулятора тратится на взлет и управление при перемещении, а не на пассивное удержание в потоке. При нулевой энергии аппарат остается в воздухе, пока соблюдены условия удержания; движение запрещено, бесплатная посадка доступна.

При недопустимом ветре или потере несущей способности срабатывает независимый механический аварийный купол. Модель завершает аварийную посадку сразу, без расхода энергии, изменения пройденного пути и дополнительных повреждений. Купол не является движителем; отдельное состояние купола не моделируется. По земле и воде аппарат не движется. Посадочная площадка всегда считается доступной.

## 3. Публичный интерфейс

Разработчик реализует описанный контракт. Тесты используют только публичный интерфейс; устройство внутренних полей не задается.

### 3.0. Общие правила

1. Число — встроенный `int` или `float`, кроме `bool`. Иной тип — `TypeError`. Строковые аргументы должны быть `str`, иначе `TypeError`.
2. Сначала проверяются типы **всех** аргументов, затем конечность и диапазоны значений, затем правила домена. `NaN`, `inf`, `-inf` — `ValueError`. При нескольких ошибках одного класса текст и выбор параметра не фиксируются. Большой `int`, например `10**400`, вне диапазона должен дать `ValueError`, а не ошибку преобразования в `float`.
3. Метод с исключением не меняет ни одного публичного атрибута (атомарность). Успешный метод изменяет только перечисленные в его описании хранимые атрибуты; производные свойства пересчитываются.
4. Величины хранятся как `float`, счетчики как `int`, флаги как `bool`. Имя сохраняется без удаления пробелов по краям; пустое или полностью пробельное имя запрещено.
5. Все интервалы с квадратными скобками включают границы. Сравнения при принятии решений точные, без epsilon и скрытого округления. Тесты результатов вычислений используют `assertAlmostEqual(..., places=6)`; типы, счетчики и флаги проверяются отдельно.
6. Методы без явно указанного возвращаемого значения возвращают `None`. Изменение состояния не требует вывода в консоль. Никаких случайных результатов, задержек или фонового течения времени.
7. Ограничения входов и суммарного пути исключают переполнение результатов. Расчет стоимости не проверяет лимит уже пройденного пути; `move` проверяет его отдельно.

Все перечисленные атрибуты только для чтения. Присвоение любому из них вызывает `AttributeError` без изменения состояния.

| Атрибут | Тип | Описание |
|---|---|---|
| name | str | Имя |
| mass_kg | float | Полная масса, кг |
| max_speed_kmh | float | Ограничение скорости, км/ч |
| energy | float | Запас энергии, [0, 100] |
| wind_speed_kmh | float | Текущий ветер, [0, 100] км/ч |
| position_km | float | Суммарный путь, [0, 10000] км |
| sail_count | int | Всегда 6 |
| working_sails | int | Исправные паруса, [0, 6] |
| sails_deployed | bool | Раскрыто ли кольцо парусов |
| is_airborne | bool | Находится ли аппарат в воздухе |
| lift_capacity_kg | float | `working_sails * 50.0`, независимо от раскрытия |
| can_takeoff | bool | Все условия взлета выполнены, включая нахождение на земле и `energy >= 5` |

Полная формула `can_takeoff`:

```python
(not is_airborne and sails_deployed and working_sails >= 3
 and 10 <= wind_speed_kmh <= 60 and mass_kg <= lift_capacity_kg
 and energy >= 5)
```

Свойство не гарантирует энергии на дальнейший маршрут. В воздухе оно всегда `False`.

Инвариант: `is_airborne` влечет раскрытые паруса, `working_sails >= 3`, `mass_kg <= lift_capacity_kg` и ветер [10, 60]. Наличие энергии в этот инвариант не входит.

### 3.4. Методы

#### 3.4.1. deploy_sails / fold_sails

```python
def deploy_sails(self) -> None:
def fold_sails(self) -> None:
```

`deploy_sails` устанавливает `sails_deployed=True` в любом состоянии, в том числе при 0 исправных парусов. Не чинит паруса и не поднимает аппарат. Повторный вызов ничего не меняет. Исключений нет.

`fold_sails` разрешен только на земле: устанавливает `sails_deployed=False`. Повторный вызов на земле ничего не меняет. В воздухе — `SkvoznyakUnsafeOperation`, без складывания и посадки. Оба действия бесплатны.

#### 3.4.2. takeoff

```python
def takeoff(self) -> None:
```

При успехе: `energy -= 5.0`, `is_airborne=True`. Путь не увеличивается. Ровно 5 единиц достаточно, после взлета аппарат в воздухе с нулем энергии.

Порядок исключений:

1. `SkvoznyakAlreadyAirborne` — уже в воздухе, в том числе при нулевой энергии.
2. `SkvoznyakSailsFolded` — паруса сложены.
3. `SkvoznyakSailsDamaged` — исправных парусов меньше 3.
4. `SkvoznyakBadWind` — ветер меньше 10 или больше 60.
5. `SkvoznyakOverloaded` — масса больше несущей способности.
6. `SkvoznyakNoEnergy(required=5.0, available=energy)` — энергии меньше 5.

#### 3.4.3. land

```python
def land(self) -> None:
```

Устанавливает `is_airborne=False`. Не тратит энергию, не меняет путь и раскрытие парусов. Доступен при нулевой энергии. На земле — полный no-op. Исключений нет.

#### 3.4.4. move

```python
def move(self, distance_km: float, terrain: str) -> float:
```

`distance_km` — конечное число (0, 1000]; `terrain` — `"air"`, `"ground"`, `"water"`. Только `"air"` допускает движение.

Скорость в км/ч: `min(max_speed_kmh, wind_speed_kmh * (working_sails / 6.0))`. Сначала делится число парусов на 6.0, затем выполняется умножение. Время в часах = `distance_km / скорость`.

| Ветер | Режим | Расход |
|---|---|---|
| [10, 30] | Обычный полет | distance_km × 1.0 |
| (30, 60] | Штормовой полет | distance_km × 2.0 |

При успехе: `energy -= расход`, `position_km += distance_km`. `is_airborne` остается `True`, даже если энергия стала равна нулю. Частичное перемещение при нехватке энергии запрещено.

Проверки в порядке:

1. Типы обоих аргументов — `TypeError`.
2. Конечность/диапазон расстояния и допустимость строки среды — `ValueError`.
3. `ground` или `water` — `SkvoznyakWrongMedium`, независимо от состояния.
4. Аппарат на земле — `SkvoznyakNotAirborne`.
5. `position_km + distance_km > 10000` — `SkvoznyakRouteLimit`.
6. Расход больше энергии — `SkvoznyakNoEnergy`.

Проверять ветер и паруса заново отдельными исключениями не требуется: публичные методы поддерживают инвариант полета. Запрос движения сам по себе не вызывает взлет или посадку.

#### 3.4.5. calculate_energy

```python
def calculate_energy(self, distance_km: float, terrain: str) -> float:
```

Параметры и первые три проверки — как у `move`. Возвращает `float`: `distance_km * 1.0` при текущем ветре ≤30, иначе `distance_km * 2.0`. Даже при ветре 0 или 100 это лишь условная оценка стоимости, не разрешение лететь.

Не проверяет раскрытие/исправность парусов, массу, положение, запас энергии и накопленный путь. Состояние не меняется. Исключения: только `TypeError`, `ValueError`, `SkvoznyakWrongMedium`.

#### 3.4.6. set_wind

```python
def set_wind(self, speed_kmh: float) -> None:
```

Устанавливает новый ветер [0, 100]. Неверный тип — `TypeError`, не конечное или вне диапазона значение — `ValueError`.

После корректной установки, если аппарат в воздухе, а новый ветер вне [10, 60], выполняется аварийная посадка: `is_airborne=False`. **Это успешное событие, исключения нет.** Энергия, путь, паруса не меняются. Возврат хорошего ветра сам по себе не вызывает взлет.

#### 3.4.7. damage_sail

```python
def damage_sail(self) -> None:
```

Событие «один парус порван». `working_sails = max(0, working_sails - 1)`. Если в воздухе стало меньше трех исправных парусов или масса превысила новую несущую способность, выполняется аварийная посадка (`is_airborne=False`). Энергия, путь и раскрытие парусов не меняются. При 0 исправных парусов — no-op. Исключений нет.

#### 3.4.8. repair_sails

```python
def repair_sails(self) -> None:
```

Только на земле: `working_sails=6`. Раскрытие, энергия, путь, ветер и положение не меняются. На земле при исправных парусах — no-op. В воздухе **всегда** `SkvoznyakUnsafeOperation`, даже если ремонт фактически не нужен.

#### 3.4.9. recharge

```python
def recharge(self, amount: float) -> None:
```

`amount` — конечное число (0, 1000]. Сначала тип (`TypeError`), затем значение (`ValueError`), затем положение: в воздухе `SkvoznyakUnsafeOperation`.

На земле `energy = min(100.0, energy + amount)`. Переполнение выше 100 отбрасывается. При полном аккумуляторе допустим вызов с корректным amount, он ничего не меняет. Зарядка не вызывает взлет.

#### 3.4.10. can_overcome

```python
def can_overcome(self, obstacle: str) -> bool:
```

Только оценка текущего состояния; не перемещает аппарат и не тратит энергию. Для всех препятствий нужны `is_airborne=True` и `energy>0`.

| obstacle | Дополнительное условие |
|---|---|
| "canyon" — каньон | Нет |
| "ridge" — горный хребет | working_sails >= 5 |
| "storm_front" — фронт бури | working_sails == 6 и wind_speed_kmh > 30 |

На земле и при нулевой энергии все ответы `False`. `True` не гарантирует энергии на заданную дистанцию: ее проверяет `move`. Иной тип — `TypeError`, неизвестная строка — `ValueError`. Регистр значим.

#### 3.4.11. get_status

```python
def get_status(self) -> dict:
```

Каждый вызов возвращает **новый** словарь ровно с ключами `name`, `energy`, `position_km`, `wind_speed_kmh`, `working_sails`, `sails_deployed`, `is_airborne`, `can_takeoff`. Значения и типы совпадают с одноименными атрибутами. Изменение словаря не влияет на объект или другой снимок. Сам метод состояние не меняет и исключений не выбрасывает.

#### 3.4.12. Сводка возвращаемых значений и исключений

Сигнатуры и типы аргументов даны выше. В сигнатурах `float` обозначает числовой параметр: разрешены встроенные `int` и `float`, кроме `bool`, по правилу 3.0. Отсутствие доменных исключений не отменяет стандартную ошибку вызова Python при неверном количестве аргументов; такие вызовы не входят в TCS.

**Then:** Запрещенные среды не меняют состояние; итог 10 км, энергия 85. Все неуспешные операции атомарны; после обработанного отказа сценарий продолжается.

#### TC-40. Починка между рейсами

**Given:** Масса 300, энергия 20.

**When:** Взлет, 10 км; повреждение и посадка; сложить, ремонт, зарядить 1000; раскрыть, взлететь, 20 км.

**Then:** Один разрыв сажает тяжелый аппарат; итог путь 30, энергия 75, 6 парусов, в воздухе. Все неуспешные операции атомарны; после обработанного отказа сценарий продолжается.

### 4.4. Тест-план

Полный план: [TEST_PLAN.md](TEST_PLAN.md). Среда — Python 3.10+, стандартный `unittest`. Сначала выполняются 32 модульных теста TC-01…TC-32, затем 8 сценарных TC-33…TC-40; итоговый критерий — весь набор без ошибок, падений и пропусков на согласованном коммите реализации.

Проверяются публичный контракт, позитивные и негативные пути, классы эквивалентности, границы, приоритет исключений, атомарность, переходы состояний и независимость снимков. Замечания B/C обрабатываются в RESPONSES.md, изменения — в CHANGELOG.md. Существенное изменение ТЗ после заморозки требует повторного ревью.

## 6. Исключения

### 6.1. Иерархия

Все исключения наследуют `Exception`: `CrazyVehicleError` → `SkvoznyakError` → каждое из следующих доменных исключений.

| Исключение | Условие |
|---|---|
| SkvoznyakAlreadyAirborne | Повторный взлет |
| SkvoznyakSailsFolded | Взлет со сложенными парусами |
| SkvoznyakSailsDamaged | Меньше трех парусов на взлете |
| SkvoznyakBadWind | Ветер не годится для взлета |
| SkvoznyakOverloaded | Масса превышает несущую способность |
| SkvoznyakNoEnergy | Недостаток энергии на взлет/движение |
| SkvoznyakWrongMedium | Попытка перемещения/расчета по земле или воде |
| SkvoznyakNotAirborne | Воздушное перемещение с земли |
| SkvoznyakRouteLimit | Превышение накопленного пути 10000 км |
| SkvoznyakUnsafeOperation | Складывание, ремонт, зарядка в воздухе |

### 6.2. Данные ошибок

`SkvoznyakNoEnergy(required: float, available: float)` поддерживает позиционные и именованные аргументы. Публичные `required`, `available` имеют тип `float` и отражают необходимый и текущий запас. Проверки конструктора исключения на недопустимых аргументах вне рамок; тесты передают допустимые числа.

Остальные доменные исключения принимают строку-сообщение. Текст сообщений не является контрактом и тестами не сравнивается. Ошибки аргументов — стандартные `TypeError` и `ValueError`; ими нельзя заменять доменные исключения.

### 6.3. Порядок проверок

Общий приоритет: типы → значения → доменные условия. Внутри доменных условий порядок указан отдельно у методов `takeoff`, `move`, `recharge`. Проверка не должна заменяться одним общим `if not can_takeoff`: вызывающая сторона должна получить конкретную причину отказа. Успешные события аварийной посадки исключений не выбрасывают.

## 7. Что вне рамок

Реальная аэродинамика, направление ветра, подъемные потоки по отдельности, высота, курс, время аварийного снижения, столкновения, травмы и выбор площадки. Ветер — единственный скалярный показатель пригодности воздушного потока. Между действиями не происходит дрейфа. Не моделируются отдельные паруса по номерам, изменение массы, груз, другие транспорты, GUI, сохранение, сеть и многопоточность. Ремонт и зарядка на земле мгновенные; инфраструктура мастерской и источника питания считается доступной.
